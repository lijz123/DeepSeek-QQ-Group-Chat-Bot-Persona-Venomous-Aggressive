# QQ 群聊机器人

基于 Python、OneBot v11 与模型服务的群聊机器人。此发布副本保留当前代码功能，但不包含作者的账号、密钥、群聊日志、登录状态和私人图片。

**默认使用 DeepSeek 配置示例；下载后必须填写自己的配置。** NapCat 负责登录 QQ，机器人程序只连接 NapCat，不代替 QQ 登录。

## 已包含的能力

- 理解优先的对话、分段消息合并、回复对象与话题追踪。
- 多人短时间同时提问时分别处理，并使用 QQ 原生引用区分对象。
- 日常聊天、互怼和骂人：同一条成员输入的整轮正文累计最多 **100 字符**，自动补发共享额度。
- 明确的代码、调试、写作等内容任务保留完整输出；**不套用日常 100 字限制**，但仍受模型、协议与平台的实际条件限制。
- 按需公开网页搜索、立即／定时提醒；是否可用以配置和实际服务回执为准。
- 生成并发送 `.py`、`.c`、`.txt` 文件：没写后缀时按内容选择，只在实际上传得到确认后报告成功。
- 管理员聊天指令、语音等可选模块保留；公开示例默认关闭管理员权限和语音，不包含任何预设私人账号。

生成的代码不保证正确。本程序不会因为语法检查通过就替你执行代码、安装依赖或烧录硬件。

## 1. 准备环境

以下步骤针对 **Windows**，在项目文件夹中操作。可在资源管理器的文件夹地址栏输入 `cmd` 后回车，打开位于当前目录的命令提示符。

建议使用 Python **3.11 或更新版本**并安装时启用 PATH。源码使用现代 Python API；本发布流程仅在 Python **3.15** 上进行了离线验证，没有完成所有 Python／操作系统／NapCat 版本的兼容矩阵。

```bat
python --version
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
```

公开启动脚本会优先使用本项目 `.venv\Scripts\python.exe`；不存在虚拟环境时才使用 PATH 中的 `python`。双击运行也遵循这个顺序。

依赖范围在 `requirements.txt`：aiohttp、PyJWT（含加密依赖）、psutil。没有锁定全部依赖版本，因此不是逐字节可重复构建。安装依赖需要自行联网。

## 2. 先运行离线检查

```bat
python tools/run_offline_tests.py
```

该入口先将公开源码复制到独立临时目录，不带入你的配置、登录状态或运行数据库；测试生成的缓存和数据库也只留在临时副本。它使用合成消息、假模型和假 OneBot，不登录 QQ、不调用真实模型，不执行生成的 Python／C 文件。部分检查会临时启动只绑定本机回环地址的模拟服务或写入临时目录。

也可以单独运行：

```bat
python tests/selftest.py
python tests/dialogue_selftest.py -v
python tests/contextual_output_tests.py .
python tests/file_delivery_tests.py .
```

`selftest.py` 使用独立的默认配置夹具，不读取你的私人 `config.json`。其他专门测试覆盖当前日常限长和文件协议。离线通过证明模拟流程和断言成立，**不等于你自己的模型、QQ、NapCat 和群文件权限已完成真实联调**。

## 3. 创建本机配置

首次使用时复制示例：

```bat
copy config.example.json config.json
```

不要覆盖已经填写好的本机配置。`config.json` 已在 `.gitignore` 中，禁止上传到 GitHub。

### 模型

公开示例使用：

- `llm.provider`：`deepseek`
- `llm.base_url`：DeepSeek 的接口地址示例
- `llm.api_key`：`env:DEEPSEEK_API_KEY`
- `llm.model`：示例模型名，按你的服务端实际可用模型核对

在当前命令提示符中设置你自己的 Key：

```bat
set "DEEPSEEK_API_KEY=替换成你自己的Key"
```

然后**在同一个命令窗口**运行 `start.bat`；这样子进程才能继承这次设置。若要以后直接双击启动，请自行在 Windows 用户环境变量中设置同名变量，并重新打开启动窗口；不要把 Key 写到要发布的脚本或文档中。

模型请求可能消耗你所配置服务的额度。项目不会提供可公用的 Key，也不会保证任何 ChatGPT 套餐都能当作 API 额度使用。

### OneBot

在 `config.json` 中核对：

```json
"onebot": {
  "ws_url": "ws://127.0.0.1:3001",
  "access_token": "填写你在NapCat中设置的同一个令牌"
}
```

这是字段示意，不是要求删掉配置中的其他字段。访问令牌由你自己生成；两端保持一致。令牌应只保存在你本机的私人配置里。此处不要直接填环境变量引用字符串，当前 OneBot 客户端会将该字段作为令牌原文使用。

`groups.whitelist` 可限制允许工作的群。公开示例不带任何真实群号；如果不想机器人在所有已加入的群工作，先填写自己的白名单再上线。管理员账号列表默认为空，只有你主动启用并填写真实账号后才会获得对应聊天指令权限。

## 4. 登录 QQ：在 NapCat 中完成

本包不附带 QQ、NapCat 安装程序、账号数据或二维码。请自行按 [NapCat 项目说明](https://github.com/NapNeko/NapCatQQ) 安装与启动。

操作顺序：

1. 启动 NapCat。
2. 在它提供的登录界面，用你要运行机器人的 QQ 扫码，并在手机上确认。
3. 等待 NapCat 显示 QQ 已在线、初始化完成。
4. 在 NapCat 网络配置中创建／启用 **正向 WebSocket 服务器**，使用数组消息格式；本机部署可绑定 `127.0.0.1`、端口 `3001`。
5. 配置访问令牌，与机器人 `onebot.access_token` 保持一致。
6. 保持 NapCat 运行，再启动下面的机器人程序。

机器人不是登录工具：运行 `app/bot.py` 不会替你完成 QQ 扫码。不要把本地 OneBot 接口或 NapCat 管理面板直接暴露到公网。

## 5. 启动和停止机器人

在已设置好模型 Key、激活虚拟环境的同一命令窗口运行：

```bat
start.bat
```

也可以直接运行：

```bat
python app/bot.py --config config.json
```

公开版 `start.bat` 首次发现没有 `config.json` 时，会从示例复制一份并提示你先配置，不会直接开始请求模型。配置完成后再次运行。

日志出现已连接 OneBot、已登录账号等信息后，在允许工作的群中 @ 机器人测试。**不要同时启动两份指向同一个 QQ 的机器人**，否则可能重复回复。

- 仅停止机器人：在这个机器人命令窗口按 `Ctrl+C`。
- 重启机器人：停止旧机器人后重新运行同一命令。
- NapCat 与机器人是两个进程；只停机器人，NapCat 可以继续在线。
- 更新源码／配置后需要重启机器人，正在运行的旧进程不会自动重载。

## 6. 文件与长代码怎么请求

例如：

> 肥鱼，用 d2l 写个简单 CNN，做成文件发给我。

不要求你写扩展名：Python／d2l／PyTorch 选择 `.py`，明确 C 语言选择 `.c`，普通文字与暂不支持的其他语言选择 `.txt`。用户明确指定合法文件名／格式时优先遵从。必要澄清只在影响实现时提问；同一成员紧接回答“Python”等信息可以继续原文件任务，不能由其他成员接管。

只有明确要求“做成文件／文件发我”等才走文件分支；只说“写代码”仍可在聊天正文给出代码。不会用“马上写”冒充文件内容，也不会只根据模型声称成功就报告已发送。

文件正文不受日常 100 字限制。配文仍简短；原有群权限、限流、停止条件不取消。上传失败、超时或回执不确定时不会盲目重传；你可以先检查群文件，再决定是否重新请求。

NapCat 必须能读取程序生成的本地路径。若 NapCat 在另一台机器或容器中，需自己提供共享路径和相应部署适配，不能直接使用机器人电脑上的路径。相关代码集中在 `app/file_delivery.py` 与 `app/file_delivery_bot.py`。
